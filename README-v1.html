暖通室信息化管理平台

暖通室信息化管理平台（原“暖通设计管家”）是一个面向暖通专业设计协同的局域网 Web 工具。它以项目和子项为中心，围绕三项核心能力建设：规范校审流程、标准化设计、汇总设计文件，并通过信息化动态管理让项目背景、阶段进展、重点事项、设备修订和校审状态及时可见，帮助设计人员快速熟悉设计内容、提升设计质量，最终达到降本增效的目的。

2026-11-17 更新：平台名称与菜单已按最新需求调整，新增“平台能力”总览与“规范校审”记录模块；最新需求说明书为 需求说明书_V3_6.md / 需求说明书_V3_6.html。README 按用户要求只保留一个版本：README.md 为源文件，README-v1.html 为同内容阅读版，后续更新不再另存 README 新版本。

一、技术路线

1. 总体架构

  • 前端：React 19 + TypeScript + Vite + Tailwind CSS
  • 后端：FastAPI + Uvicorn
  • 数据存储：
    • 项目主库：server/hvac.db
    • 账户权限库：server/accounts.db
    • 上传文件目录：server/uploads
  • 运行环境：
    • 推荐：Conda 环境 hvac-design
    • 可选：系统 Python 3.11+ + Node.js 20+

2. 前端技术说明

  • 使用 React 组件化构建平台能力、项目总览、设计过程、规范校审、模板管理、账户管理等页面
  • 使用 TypeScript 维护项目、子项、任务、文件、账户权限与校审记录等数据结构
  • 使用 Tailwind CSS 快速搭建页面样式与响应式布局
  • 使用 Vite 提供开发调试与生产构建能力
  • 项目总览与设计过程均支持树图 / 列表双模式切换

3. 后端技术说明

  • 使用 FastAPI 提供 REST API
  • 使用 Uvicorn 作为本地/局域网服务启动器
  • 使用 SQLite 保存项目数据、账户数据和权限数据
  • 使用后端统一处理：
    • 登录认证
    • 项目读取与保存
    • 用户与权限管理
    • 文件上传/下载/导出
    • 表格导入账户和项目

4. 当前数据组织

  • server/hvac.db
    • 保存项目主数据、任务数据、过程记录、校审记录、文件索引、知识库等
  • server/accounts.db
    • 保存登录账户、账户角色、项目权限、子项权限
  • dist
    • 前端构建产物，后端可直接托管

三、启动方法

1. 推荐方式：双击 start_all.bat

这是根目录唯一需要点击的启动脚本。它会：

  • 自动查找本机 Conda，优先使用 hvac-design 环境
  • 检查前端依赖，必要时自动安装
  • 启动后端与前端
  • 自动打开浏览器

启动后的访问地址：

  • 前端：http://localhost:3000/
  • 后端：http://127.0.0.1:3101/

注意：

  • 会弹出后端和前端两个窗口，请勿提前关闭。
  • 后端窗口出现错误时，先看后端窗口的提示，再刷新浏览器。
  • 两个 worker 脚本是辅助文件，不需要、也不建议单独双击。
  • 隐藏窗口启动、内网部署等旧脚本已归档；如确有需要，可从 archive/整理归档-2026-11-17/旧启动脚本/ 取回。

2. 开发方式：命令行启动

首次创建环境：

conda env create -f environment.yml

已有环境更新：

conda env update -n hvac-design -f environment.yml --prune

安装前端依赖：

conda run --no-capture-output -n hvac-design npm install

启动后端（注意从 server 目录运行）：

cd server
conda run --no-capture-output -n hvac-design uvicorn app:app --host 0.0.0.0 --port 3001

启动前端：

conda run --no-capture-output -n hvac-design npm run dev

说明：一键启动实际使用后端 3101 端口、前端 3000 端口；上面的手动示例使用 3001 端口，便于与内网部署口径保持一致。

3. 不使用 Conda 的启动方式

安装前端依赖：

npm install

安装后端依赖：

python -m pip install -r requirements-server.txt

启动后端：

cd server
uvicorn app:app --host 0.0.0.0 --port 3001

启动前端：

npm run dev

4. 内网部署方式

内网部署脚本 start_intranet_server.bat 已归档到 archive/整理归档-2026-11-17/旧启动脚本/。如使用内网部署包，请从归档中取回该脚本，或按部署包内说明启动。

访问地址通常为：

  • 本机：http://127.0.0.1:3001/
  • 局域网其他电脑：http://服务器内网IP:3001/

五、页面功能简要说明

1. 平台能力

这是按新需求新增的总览入口，用业务语言展示：

  • 三项核心能力：规范校审流程、标准化设计、汇总设计文件，并标注当前状态（已实现 / 试用中 / 待实施 / 待确认）
  • 当前项目快照：主项目、子项、阶段、未关闭校审、执行重点与设计过程记录数
  • 最近动态：文件上传、状态变化、校审流转等关键操作自动留痕
  • 后续实施计划：设备台账共享与 Excel 导入、跨项目检索与导出增强、正式系统编号/链接关联

2. 项目总览

功能包括：

  • 查看当前项目和子项
  • 在树图模式与列表模式之间切换
  • 查看阶段结构、细项状态、文件挂载情况
  • 导出当前阶段或导出整个项目

3. 设计过程

功能包括：

  • 记录设计输入、收到提资、计算结果、对外提交、输出成果、出图后闭环、设计备注等过程记录
  • 在树图模式与列表模式之间切换查看阶段、分类、记录、版本与文件
  • 上传与下载过程文件
  • 跟踪设计过程留痕

4. 规范校审

这是按新需求新增的记录模块，覆盖自校、互校、专业校审：

  • 发起校审时填写阶段、校审类型、对象、校审人、整改责任人、意见与规范引用
  • 按状态和阶段筛选校审记录
  • 设计人员提交整改回复，校审人员复核通过或退回整改
  • 保留发起、整改、复核、关闭的流转记录和操作人
  • 公司正式审批与出版结论仍以公司正式系统为准，本模块只记录项目内闭环过程

5. 本机资料导入

功能包括：

  • 在自己电脑上选择资料文件夹，网页按相对层级预览文件
  • 勾选或排除文件，按阶段与类别批量归类
  • 选择目标项目与子项后上传，逐项显示进度
  • 失败项可单独重试，不要求先把文件拷到服务器共享目录

6. 标准化设计

功能包括：

  • 管理设计规范模板
  • 管理常见问题模板
  • 维护项目可复用的模板内容、阶段分类与检查要点

7. 账户管理

管理员可进行：

  • 新建账户
  • 修改账户角色
  • 按项目/子项分配编辑权限
  • 删除账户
  • 批量导入账户

8. 项目导航

功能包括：

  • 左侧按“项目 > 子项”浏览
  • 默认折叠子项，仅显示项目
  • 展开后可进入具体子项
  • 支持搜索项目或子项

9. 新建设计项目

功能包括：

  • 手动创建项目和首个子项
  • 设置项目类型、设计阶段、启用分类
  • 通过表格批量导入项目

项目导入表格默认列名：

  • 项目名称
  • 项目编号
  • 子项名称
  • 子项编号
  • 项目类型
  • 设计阶段
  • 启用分类

六、故障处理措施

1. conda was not found in PATH

处理方法：

  • 先确认本机已安装 Anaconda 或 Miniconda
  • 使用当前仓库中的最新版 start_all.bat
  • 当前脚本会自动查找常见 Conda 安装路径，不再只依赖 PATH

2. 'node' 不是内部或外部命令

处理方法：

  • 确认使用的是当前仓库中的最新版启动脚本
  • 当前脚本会优先把 Conda 环境中的 node.exe 加入 PATH
  • 如仍失败，可先手动执行：
conda run -n hvac-design npm install

3. 前端窗口提示“命令语法不正确”

处理方法：

  • 使用当前仓库中的新版启动链路
  • 当前版本已经拆分为：
    • start_frontend_worker.bat
    • start_backend_worker.bat
  • 避免了长命令直接塞进 cmd /k 的引号解析问题

4. 一键启动后网页打不开

处理方法：

  • 先检查后端与前端窗口是否仍在运行
  • 检查端口 3000 与 3101 是否被占用
  • 检查防火墙是否拦截
  • 关闭旧窗口后重新运行 start_all.bat，再刷新浏览器

5. 导出按钮点击失败

当前版本已经做过两类兼容：

  • 中文文件名导出时，后端响应头已做兼容处理
  • 即使项目当前没有上传最终文件，也会导出一个带 manifest 的 ZIP 包

如果仍失败，请检查：

  • 当前打开的是否是旧版本前后端进程
  • 是否使用了旧浏览器缓存页面
  • 端口是否仍连到旧服务

建议处理步骤：

  1. 关闭已有平台前后端窗口
  2. 重新运行 start_all.bat
  3. 刷新浏览器后重试

6. 页面上看不到已有账户

处理方法：

  • 确认后端使用的是新版本，账户现在从 server/accounts.db 读取
  • 如只有 server/hvac.db 而没有 server/accounts.db，重启一次后端让迁移自动执行
  • 再进入账户管理页面点击刷新

7. 内网部署电脑提示依赖缺失

表现：

  • FastAPI / Uvicorn 缺失
  • Python 可用但服务无法启动

处理方法：

  • 优先使用打包好的内网部署目录
  • 确认部署包内包含：
    • dist
    • server
    • runtime-hvac-design
    • start_intranet_server.bat（根目录已归档，可从归档取回）

8. 导入表格失败

处理方法：

  • 检查表头是否和 README 约定一致
  • 推荐使用 UTF-8 CSV 或 .xlsx
  • 每行至少要有主项目名称和子项名称

八、实施阶段与计划（业务口径）

阶段 业务目标 主要计划动作 当前状态与验收要点
第一阶段：资料找得到、下得来 以项目为入口集中查看和下载授权资料 选试点项目、核实权限、按需上传、查询下载与批量导出 已具备本机目录导入、树图浏览、阶段导出；跨项目检索与共享下载权限细节待补
第二阶段：设备台账共享 把现有设备 Excel 变成多人可维护的共享台账 梳理字段与映射、导入试点并核对、只更新变化行、授权协作维护 待实施；验收看导入数一致、多对多关联可查、修改可追溯
第三阶段：标准化设计复用 让新人按统一方法快速熟悉设计内容 选取真正使用的模板与阶段清单、一次配置适用项、日常只更新变化 基础模板与阶段清单已具备；模板快照和适用性配置待完善
第四阶段：规范校审闭环 意见、整改、复核、关闭过程可追溯 专业负责人确认最少必填字段、选真实项目试用 本轮新增校审记录与流转，状态为“试用中”；正式审批与出版仍由公司系统负责

每个阶段都可以单独验收、单独回退，不要求先完成全部安全整改或测试体系建设后才开始。状态口径以需求说明书 V3.6 第 13 章为准，需求描述不等于功能已实现。
