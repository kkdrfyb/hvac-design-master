01

这个项目要解决什么

需求来源：基础版 v0、V1~V3.1 需求说明书、PLAN 系列，以及 MD_collect/问题.md 里用户逐条提出的现场问题。

一句话目标（需求基线原文）：

「把设计过程记录对、存完整、找得到。」

面向暖通专业设计工程师的低侵入式辅助工具；不替代设计软件、不改变既有习惯， 只做「随用随查、随时补录」的过程留痕，强调可追溯、可解释、稳定性高于智能化。 — 暖通设计管家｜需求说明书（基础版 v0）

需求可以拆成三层

A · 记录与归档

设计过程怎么存

  • 三阶段：方案 / 初步设计 / 施工图
  • 七类过程：设计输入、收到提资、计算结果、对外提资、输出成果、出图后闭环、设计备注
  • 每阶段有明确的输入清单、计算成果、跨专业提资与交付文件清单
  • 文件按「系统 + 阶段 + 前置信息」分类存储；默认展示最新版，可展开历史版本
  • 页面只列名称与附件名，不做内容对比；支持单文件 / 分类 / 阶段 / 整项目一键下载
B · 模板化产出

怎么降低重复劳动

  • 设计说明模板：用「设计输入 + 计算结果」的结构化字段填关键数据，其余为固定标准文本
  • 目标：降低同类电站 / 同类厂房项目之间的描述差异度
  • 一键生成设计说明 DOCX + PDF，作为阶段成果入库并版本化
  • 批量把关键字段写入已上传 DWG 的图框属性，生成新版本、原件不覆盖
  • 按「项目类型 + 设计阶段」管理模板，模板与字段清单由用户提供
C · 管理与追溯

多人多项目怎么用

  • 项目 > 子项树形导航、搜索、默认折叠
  • 阶段完成手动确认、执行重点、历史阶段对比、最近业务记录
  • 跨项目浏览同类资料（如「制氯站给电气条件」）
  • 管理员建号、按项目 / 子项授权、表格批量导入账户与项目
  • 文件夹扫描：把已有本地目录结构映射成设计过程记录

明确划过的边界（冻结项）

不做规范条款自动判断 不做自动计算 / 校核 不解析文件内容 不做审批流程 不做自动 OCR / AI 生成（V4+）

这些边界来自基础版 v0 与 PLAN.md 的 V1 冻结定义，但后续的 V3.1 与实际开发已经把「权限体系」「DWG 写入」「PDF 文本抽取」纳入范围 —— 这本身就是一个需要收口的需求矛盾，见第 03 节。

P-02产品与需求优先

最有价值的两项能力仍是占位实现

「设计说明模板真填充」与「DWG 图框批量填充」是本项目区别于通用任务/网盘工具的核心，但当前只做到了接口与文件产出：DOCX/PDF 是手写极简格式拼纯文本；DWG 接口只复制一份文件改成 *_filled.dwg 并记为新版本，图框属性一个字节都没写，也没有 AutoCAD 脚本引擎与失败回滚。

依据：server/app.py 的 fill_dwg_frames（约 3481 行起，shutil.copyfile(file_path, stored_path)）、_generate_docx / _generate_pdf（约 2397 行起）；round-qa-2026-03-22.md 第 3 轮标注「最小占位实现、未运行测试」；round-qa-2026-03-28.md 第 4 轮 P0-6 明确「拿到 AutoCAD 脚本和字段清单后再做真实落地」。
